# Security and data handling

Do not post passwords, SSH private keys, access tokens, institutional data, patient records, confidential genome sequences or unlicensed model assets in issues or commits.

For a suspected security vulnerability, contact the repository maintainers privately through an appropriate institutional or GitHub security channel rather than disclosing exploit details in a public issue. The project presently has no published guaranteed vulnerability-response SLA.

Remote execution is optional. Keep SSH host keys verified, use minimal authorized credentials, avoid arbitrary shell code from untrusted inputs, and audit every generated batch script before submission. Treat AF3 datasets, model weights, external tools and cloud services according to their own terms and licenses.
